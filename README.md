# Kalpi

Kalpi — статический исследовательский прототип политического опросника по Израилю. Он сопоставляет ответы человека с документированными позициями партий по конкретным политическим вопросам.

Это не рекомендация, за кого голосовать, и не прогноз результатов выборов. Итог показывает только степень совпадения с доступной исследовательской матрицей и обязательно учитывает, насколько эта матрица заполнена.

## Что можно сделать на сайте

- ответить на 27 фиксированных вопросов по шкале от `-2` («категорически против») до `+2` («полностью за»), выбрать нейтральный ответ `0` или пропустить вопрос;
- сравнить свои ответы с позициями 12 активных партий и списков из текущего набора данных;
- увидеть лучшее совпадение, полный рейтинг, совпадение известных позиций и покрытие данных по каждой партии;
- отметить любое количество особенно важных для себя вопросов. Отмеченный вопрос с содержательным ответом получает двойной вес в рейтинге;
- посмотреть, на каких вопросах совпадение, расхождение или нехватка данных повлияли на результат;
- открыть карточку «партия × вопрос»: в ней есть проверяемое утверждение, статус позиции, её scope, источники, дата и тип источника;
- увидеть пользователя и партии по пяти политическим осям. Если по оси недостаточно данных, партия не рисуется искусственно в центре;
- просмотреть качество матрицы: заполненность по партиям, вопросам и осям, оставшиеся пробелы и происхождение источников.

## Методология

### 1. Вопросы и ответы

Каждый вопрос и каждая позиция партии кодируются на одной шкале от `-2` до `+2`. Нулевой ответ — полноценная позиция «нейтрально / не уверен», а «пропустить» означает, что этот вопрос вообще не участвует в расчёте.

Для каждой пары «партия × вопрос» хранится значение позиции, статус, confidence, scope и ссылки на evidence. Позиция может быть `known`, `mixed`, `historical` или `insufficient_data`.

- `known`, `mixed` и `historical` могут участвовать в расчёте, но их влияние зависит от confidence;
- `insufficient_data` не считается нейтральной позицией и не создаёт ложного совпадения;
- evidence, относящееся к партии-компоненту нового списка, лидеру или отдельному депутату, маркируется соответствующим scope и получает понижающий коэффициент.

### 2. Совпадение по одному вопросу

Для известной позиции партии совпадение рассчитывается так:

```text
agreement_q = 1 - abs(ответ пользователя - позиция партии) / 4
```

Полное совпадение даёт `1`, противоположные ответы — `0`. Для промежуточных случаев получается пропорциональная величина между ними.

### 3. Вес вопроса, confidence и покрытие

Обычный отвеченный вопрос имеет вес `1`. Если пользователь отметил его звёздочкой как важный, его вес становится `2`. Это влияет на рейтинг и покрытие данных, но не меняет карту пяти осей.

Вклад известной позиции дополнительно умножается на её confidence. Поэтому более уверенная позиция влияет сильнее, а ограниченный scope получает дополнительное понижение.

Сначала считается среднее взвешенное совпадение только по позициям, которые можно использовать. Затем отдельно считается покрытие: какая доля веса отвеченных вопросов имеет у партии пригодную позицию с учётом confidence.

```text
final_score = agreement * coverage + 0.5 * (1 - coverage)
```

При низком покрытии итог приближается к `50%`. Так партия с идеальным совпадением по двум известным вопросам не получает искусственные `100%`, если по остальным отвеченным вопросам данных нет.

### 4. Пять осей

Помимо рейтинга Kalpi строит координаты по пяти осям:

1. экономика и перераспределение;
2. безопасность и территории;
3. религия и государство;
4. гражданские и социальные права;
5. институты и верховенство права.

Координаты не задаются партиям вручную. Они выводятся из связей вопросов с осями (`axis_weights`) и известных партийных позиций. Для каждой оси действует отдельный минимальный порог покрытия: если он не пройден, результат остаётся `insufficient_data`, а не заменяется центром шкалы.

## Что Kalpi пока не делает

- Не подбирает следующий вопрос адаптивно: все 27 вопросов показаны в фиксированном порядке.
- Не выбирает партии по текущим опросам и не обновляет состав списков автоматически. В приложении используется фиксированный набор из 12 активных партий/списков.
- Не строит прогноз прохождения электорального барьера и не показывает «картину коалиции» или заявленные красные линии.
- Не гарантирует, что каждая позиция является свежим заявлением 2025–2026. Это исследовательский снимок, а не постоянно обновляемый мониторинг кампании.

## Данные и проверяемость

Начальный dataset — рабочая исследовательская матрица, собранная по программам, идеологическим профилям, публичным заявлениям и отдельным голосованиям. В текущих `sources.json` источники помечены `verification_status: "previously_researched_2026-08-08"`.

Для публичного использования это означает простое правило: результат полезен как прозрачное сравнение по имеющимся данным, но не должен подаваться как окончательная характеристика партии. Перед релизом нужно повторно проверить ссылки, даты, формулировки утверждений и слабые или контекстные источники.

## Программный доступ

Данные — обычный JSON, а математическое ядро экспортируется из `core.js` как CommonJS-модуль в Node и как `window.KalpiCore` в браузере. Например:

```js
const fs = require('node:fs');
const Core = require('./core.js');
const load = (name) => JSON.parse(fs.readFileSync(`data/${name}.json`, 'utf8'));

const result = Core.scoreParty({
  partyId: 'yisrael_beytenu',
  answers: { civil_marriage: 2, haredi_draft: 1 },
  questions: load('questions'),
  positions: load('positions')
});
console.log(result);
```

Таким образом другой скрипт, notebook или будущий backend может использовать ту же математику без HTML-интерфейса.

## Файлы данных

Канонические редактируемые данные:

- `data/axes.json` — пять осей и подписи полюсов;
- `data/parties.json` — партии и лидеры;
- `data/questions.json` — вопросы, коэффициенты для осей и связи с осями;
- `data/positions.json` — матрица `party × question`; неизвестное всегда записано как `status: "insufficient_data"`;
- `data/sources.json` — источники и provenance.

`data/default-data.js` — автоматически генерируемая браузерная копия этих JSON. Она нужна только потому, что браузеры обычно блокируют `fetch()` соседних файлов при открытии страницы через `file://`.

## Обновление исследовательских данных

Данные обновляются только в репозитории: отредактируйте канонические JSON, сохраняя обязательные поля `*_en`, `*_ru` и `*_he` для названий партий, лидеров, осей, полюсов, вопросов и групп. Затем выполните:

```bash
python tools/build_data_bundle.py
```

Перезагрузите страницу. Для локального HTTP-запуска используйте `start.bat`; при открытии через `file://` обновлённый bundle обязателен.

Проверить, что bundle соответствует JSON:

```bash
python tools/build_data_bundle.py --check
```

## Формат позиции

```json
{
  "party": "yisrael_beytenu",
  "question": "civil_marriage",
  "value": 2,
  "status": "known",
  "confidence": 0.98,
  "entity_scope": "PARTY",
  "evidence": ["src_ndi_platform"]
}
```

Допустимые `status`: `known`, `mixed`, `historical`, `insufficient_data`.

Для нового объединённого списка evidence старой партии или отдельного лидера следует маркировать `COMPONENT_PARTY` / `LEADER`: ядро автоматически уменьшает их эффективный вес и интерфейс показывает contextual badge.

## Проверка

```bash
node --test tests/*.test.js
python tests/bundle.test.py
python tools/build_data_bundle.py --check
```

## Рекомендуемый запуск на Windows

Запускайте `start.bat`, а не `index.html` двойным кликом. Страница откроется через локальный HTTP-сервер и будет читать канонические JSON напрямую при каждой перезагрузке.

Если открыть `index.html` напрямую через `file://`, браузер не разрешает странице читать соседние JSON. В этом режиме используется `data/default-data.js`, поэтому после любой правки JSON нужно выполнить `python tools/build_data_bundle.py`.
