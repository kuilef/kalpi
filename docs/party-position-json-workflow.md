# Как добавлять позиции партий в v2

Сейчас `data/positions.json` — очередь явных пробелов. Каждая строка описывает одну пару «партия × вопрос». Не меняйте вопрос, тематическую группу (`family`) или formula, когда добавляете данные.

Для отдельного исследования всех 23 вопросов одной партии используйте готовый [prompt для ChatGPT](chatgpt-party-position-research-prompt.md). Он возвращает candidate package, который требует ручной проверки перед переносом в canonical data.

## Что отправлять в ChatGPT

Для одного вопроса и одной партии передавайте:

- ID и оба полюса из `data/questions.json`;
- существующие source records, если они релевантны;
- требование вернуть только JSON без пояснений вне JSON.

Ответ должен иметь форму:

```json
{
  "party": "party_id",
  "question": "question_id",
  "value": -0.5,
  "confidence": 0.8,
  "status": "known",
  "entity_scope": "PARTY",
  "evidence": ["source_id"],
  "explanation_ru": "Короткое нейтральное объяснение связи источника и позиции.",
  "last_verified": "2026-08-11"
}
```

`value` означает положение на отображаемой шкале: `-1` ближе к левому полюсу вопроса, `+1` ближе к правому. Это не общий лево-правый ярлык партии.

## Перед импортом

1. Проверить, что источник реально говорит о данной партии и этом вопросе.
2. Добавить новый источник в `sources.json`, если его ID ещё нет.
3. Заменить ровно одну существующую пустую запись в `positions.json`; не добавлять дубликат.
4. Указать `confidence`, `explanation_ru` и `last_verified`.
5. Запустить validator и тесты.

`null` и `confidence: 0` означают недостаток данных. Их нельзя заменять значением `0`: это содержательная центральная позиция.

Публичный ranking включается только отдельным решением после evidence review и настройки release coverage gate.
